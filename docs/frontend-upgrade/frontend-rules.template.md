# Yansivra 前端规则模板

> 当前只是文档模板，不是已生效的根 AGENTS.md，不会因为合并此规划 PR 自动修改用户全局代理行为。
> 实施时先读取现有规则；将必要内容增量合入已有前端作用域，或由其引用本文。涉及 UI 包和 Electron renderer 的执行者都要使用同一设计系统。不得覆盖现有全局模型路由、其他项目配置或全部 AGENTS.md。
> 本模板是对原文「方法 4、提示词约束」的产品化改写，不是原文逐字模板。主计划：[README.md](README.md)；技能步骤：[skills-workflow.md](skills-workflow.md)。

## 产品与工作范围

你在改进已经运行的 Yansivra 投资研究与复盘桌面应用，不是在从零制作 SaaS 落地页。

保留「总览、研究、复盘、资产」入口与既有功能。主要修改总览、研究阅读与依据侧栏、判断复盘。资金、报告、模型输出及错误状态必须来自真实的已有契约。

用户希望界面有明显的设计完成度和有记忆点的动态反馈；不要将所有视觉变化压缩成调整圆角、间距和几条 hover 样式。

## 必须采用的开发流程

1. 先核验 frontend-design 与 ui-ux-pro-max 的实际入口。安装不等于已调用，必须读取并留下真实工作记录。
2. UI UX Pro Max 按已检测的 Electron/React 栈检索；检查结果是否适配，空结果或离题不伪造成功。
3. frontend-design 结合产品内容制定构图、字级和材质，并做一次反模板自评。
4. 一份 MASTER 管理全局规范，三个 page 文件只记录差异。已有决定先读再改，不生成两套冲突设计系统。
5. 先做开发专用静态样稿与截图，再复用现有数据链路接线，最后叠加状态动效。
6. 设计工具、组件库与测试工具按实际任务使用，不无条件安装整套工具链。

开发技能不放入 Yansivra 的 `skills/`、SkillHub 或 Electron 打包资源。未经用户授权不覆盖全局配置、不自动提权或进行系统级修改。

## 视觉约束

以主计划的暖白与墨蓝作为兼容基线，引用语义 token，不到处硬编码颜色。暗色主题是正式支持状态，不是验收后才补的反色模式。

表现力集中在总览的一张正式“研究档案”主视觉；研究、依据、快照和复盘使用同一母题的轻量变化。主视觉应有可辨认的材质、遮挡和光源，不用粗糙旋转矩形或通用机器人充数。

有层级地使用纸面、侧边标记、正文区和紧凑数据条目。不要把所有内容拆成相同圆角、相同阴影、相同尺寸的卡片。

禁止默认蓝紫渐变、大标题加三卡片、满屏玻璃、随机粒子、滚动劫持和全文打字机。也不要把暖白衬线、报纸分栏、装饰编号、全大写眉题、每个按钮后的箭头作为另一套固定公式。

编号必须有真实顺序，标记必须表达真实状态，标签必须帮助理解。金融正负、任务成功和模型立场不能混用一种颜色冒充一种语义。

图表与长正文允许纯色干净底。纸纹与光感只能在不妨碍阅读的装饰区域；不要照搬“每块背景必须有噪点”的文章提示词示例。

字体通过设计检索和 Windows 实际截图选定。中文阅读、数字对齐和缩放优先，不为去掉某一默认字体重写全部 UI。正文、辅助文字和按钮不压到难以阅读的小字。

## 素材与组件

正式素材必须本地化，登记来源、许可、大小和用途，设宽高/比例及失败回退。原文效果图和视频只作参考，不当作已获授权的应用素材。

不要运行时请求随机图、拉取外部字体或放未标注的虚构财务图表。现有 Lucide/Radix 与图表可保留，不因文章列举多个库就全部更换。

允许按需选用 Magic UI Animated Beam 等少量局部组件。安装前读实际源码与当前 API，核查重复次数、可见性、卸载和主题参数。最多一种新增动画运行时，不能顺手迁移框架或初始化覆盖工程。

如组件不合适，记录拒绝理由再使用本地替代；不能没读源码就写“已参考并复用”。

## 动效约束

动效必须解释状态变化：新增采集结果汇聚、所选章节与依据对应、写入成功后追加复盘。静态最终状态从第一帧就可用，业务不能等待动画结束。

采集分组不等于 Agent；planned=0 不等于完成；所有数据取回也不等于报告综合完成。partial、失败、取消、中断和不一致数据都要诚实显示。

恢复已有结果时不补播“新完成”；重复状态不反复闪动。以 runId、reportId、section key、entryId、review.id 隔离相应展示状态。

不动画 Allotment 栏宽，不为过场给整个工作台或 form 添加会导致重挂载的 key。助手输入、图表实例、原判断、草稿和滚动位置不能丢失。

处理当前 ambient 短周期与无限循环组合。终态、隐藏和 reduced-motion 下停止非必要装饰；返回页面不集中补播。初次渲染就用 CSS 尊重 reduced-motion，而不只等 hook 的 effect。

曲线按用途选择。linear 与 ease-in-out 并不相同，不将原文示例中的术语混用变成错误规则。

## 数据与安全边界

不改 Pi RPC、Agent 生命周期、行情 Provider、金融计算、凭据、journal 存储、现有数据目录和打包身份。

历史报告打开正确 reportId；diff 必须属于当前报告；snapshotMode 不注入新行情或新报告、不出现再记录判断动作。

EvidenceInspector 保留 runId 与 capabilityId 的匹配。证据是执行记录/摘要时，不展示虚构 PDF 页码、原文定位和已核验印章。

判断与复盘等待真实落盘成功；失败保留草稿、requestId 与错误。不得为了完成动画先插入伪成功记录，不用视觉变更放松幂等与防重。

所有演示内容明确标注；不能把开发 fixtures 变成生产错误回退。未取得真实数据时，不生成假收益、假总数、随机行情和“胜率”。

## 文案

动作使用清楚、稳定的词：开始研究、阅读报告、查看依据、记录判断、追加复盘、重试。

空态解释下一步，错误解释失败与恢复方式。必要的金融术语可以保留；不用夸张营销、无根据的效率数字、挑衅式文案或机械的每句15字限制。

## 验收与记录

三页需提交同尺寸明暗截图；关键交互需录屏。检查窄容器、Windows 缩放、长中文、键盘焦点、reduced-motion、无数据和真正失败场景。

运行当前脚本定义的相关测试，注明命令、日期、实际结果与未验证范围。原 PR 的测试数量、静态源码推断、浏览器预览不能冒充本次 Windows Electron 实测。

Skill 调用记录、设计系统、素材清单、组件依赖差异、截图和回归共同构成交付证据；任何一个 Skill 名称本身都不是质量保证。

## 优先级

用户的本次要求、既有仓库约束与数据正确性优先；然后是本轮定稿 MASTER、页面差异与本文；Skill 的通用建议和参考网站只提供候选，不能自动覆盖已确认的产品方向。

新冲突先记录并做最小范围协调，不重新设计整个产品。时间不足优先移除背景循环、封面动画等可选装饰，保留正式静态素材、清楚排版和真实交互。
